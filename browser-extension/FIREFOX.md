# xADKiller Firefox 1.5.0 Stable

Firefox port of the existing xADKiller browser extension, with STANDARD/ULTRA network filtering, TITAN session protection, local Adaptive Memory, Shadow DOM filtering, Auto-Skip, custom rules, per-site exceptions and recovery controls. Polish and English UI are included.

## Distribution

The GitHub release contains an **unsigned ZIP for manual submission to Mozilla Add-ons (AMO)**. GitHub Stable describes this project's release channel; it does not mean Mozilla has reviewed, signed or published it. Normal permanent installation in release Firefox requires Mozilla's signed package. Minimum Firefox version: 142.

## Build and check

Requires Node.js 24 and npm. From `browser-extension`:

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run build:firefox
node tests/firefox-build-contract.mjs
npm run lint:firefox
npm run test:firefox
npm run package:firefox
```

Set `FIREFOX_BIN` if Firefox is not at its normal Windows path or available as `firefox` on other systems. Runtime tests create a temporary profile and test-only extension copy. They add DNR feedback and a fixed loopback test driver only to that copy. They do not enable Firefox system access or alter the user's browser profile. No test driver or debug permission is included in the release ZIP.

Output: `dist/firefox` and `web-ext-artifacts/xADKiller-Firefox-v1.5.0.zip`.

The production build is offline and deterministic for a fixed source commit. `firefox/data-snapshot.json.gz` is a gzip-compressed JSON map containing frozen **data**, generated by the repository's existing filter builders on 2026-10-30. It contains no downloaded executable extension logic. Build metadata includes the source commit; when reproducing from an archive without `.git`, set `XAD_SOURCE_COMMIT` to the release tag's commit SHA. Sources include every builder, the frozen data input and the lockfile.

To deliberately refresh the data snapshot: `npm run build`, then `node tools/capture-firefox-data.mjs`, then rebuild and run the Firefox checks. Review the changed data before publishing another version.

## Firefox adaptations

- Explicit background script order replaces the Chromium service worker.
- Groups up to 100 same-action domains per dynamic rule. All 16,000 STANDARD / 24,000 ULTRA intelligence domains remain covered, with room for custom domains, exceptions and live data below Firefox's 5,000-rule limit.
- Clones page configuration into Firefox's page realm so disable, allowlist and recovery settings reach the MAIN-world protection.
- Packages core ad-path patterns already handled by the preflight layer as DNR rules for offline startup.
- Compacts rule JSON to satisfy AMO's 5 MB per-file parser limit.
- Omits unsupported Chromium badge/matched-request APIs. No invented blocked-request count is displayed.
- Reuses data-only feed validation. Failed, stale or unavailable feeds do not remove packaged protection.

## Manual AMO submission

1. Open the Mozilla Add-on Developer Hub and choose **Submit a New Add-on**, listed on addons.mozilla.org.
2. Upload `xADKiller-Firefox-v1.5.0.zip` from the GitHub release.
3. Supply `xADKiller-Firefox-v1.5.0-source.zip` as the source package. Use the reproduction instructions above and the commit recorded in `SOURCE_COMMIT.txt`.
4. Use the listing copy in `FIREFOX_AMO.md`, and link the repository's `PRIVACY.md`.
5. Review the developer agreement, license selection and submission declarations yourself, then submit. No AMO submission or Mozilla signing is performed by the GitHub workflow.
6. After signing/review, download the signed XPI and attach it to the same GitHub release with its checksum. Keep the unsigned submission ZIP for reproducibility.

For local development, open `about:debugging#/runtime/this-firefox`, choose **Load Temporary Add-on**, and select `manifest.json` from the unpacked ZIP. This installation lasts until Firefox restarts.

## Limitations

No ad blocker guarantees removal on every website. Same-origin ads and changing page markup may need new rules. Protected Firefox/Mozilla pages do not allow normal content-script filtering. TITAN static boost activates only within the available browser rule budget. Remote feed failures are reported locally; the extension does not upload browsing history, page contents or adaptive memory.
